# Аудит безопасности проекта Gunfire Airsoft Clone

В ходе анализа кода были выявлены следующие потенциальные уязвимости и структурные недостатки, требующие внимания.

## 🔴 Критические уязвимости (High Severity)

### 1. Отключена защита CSRF в корзине покупок
**Файл:** `apps/cart/views.py`
**Описание:** Функции `add_to_cart`, `update_cart_item` и `remove_from_cart` используют декоратор `@csrf_exempt`, который полностью отключает проверку CSRF-токена.
**Риск:** Злоумышленник может создать вредоносную страницу, которая при посещении аутентифицированным пользователем будет скрыто добавлять или удалять товары из его корзины без его ведома.
**Рекомендация:**
1. Удалить декоратор `@csrf_exempt` со всех view-функций в `apps/cart/views.py`.
2. Убедиться, что HTMX-запросы передают CSRF-токен. Обычно это делается добавлением `hx-headers='{"X-CSRFToken": "{{ csrf_token }}"}'` в шаблон или (лучше) глобальной настройкой HTMX:
   ```javascript
   document.body.addEventListener('htmx:configRequest', (event) => {
       event.detail.headers['X-CSRFToken'] = '{{ csrf_token }}'; // Или получение из cookie
   });
   ```

## 🟠 Средний уровень риска (Medium Severity)

### 2. Сравнение HMAC-сигнатуры подвержено атакам по времени (Timing Attack)
**Файл:** `services/nowpayments_service.py`
**Метод:** `check_signature`
**Описание:** Сравнение сигнатур выполняется с помощью обычного оператора `==`:
```python
return signature == received_sig
```
**Риск:** Теоретически возможно вычислить правильную сигнатуру, анализируя время ответа сервера (Timing Attack), так как обычное сравнение строк прерывается при первом несовпадении символов.
**Рекомендация:** Использовать функцию `hmac.compare_digest` для безопасного сравнения:
```python
import hmac
# ...
return hmac.compare_digest(signature, received_sig)
```

## 🟡 Низкий уровень риска / Рекомендации (Low Severity)

### 3. Предсказуемая генерация номеров заказов
**Файл:** `apps/orders/models.py`
**Метод:** `Order.save`
**Описание:** Для генерации случайной части номера заказа используется модуль `random`:
```python
import random
random_str = ''.join(random.choices(chars, k=8))
```
**Риск:** Модуль `random` не является криптографически стойким. Злоумышленник, имея достаточно примеров номеров заказов, может предсказать следующие номера.
**Рекомендация:** Использовать модуль `secrets`:
```python
import secrets
# ...
random_str = ''.join(secrets.choice(chars) for _ in range(8))
```

### 4. Использование `psycopg2-binary` в продакшене
**Файл:** `requirements.txt`
**Описание:** Используется библиотека `psycopg2-binary`.
**Риск:** Разработчики библиотеки PostgreSQL рекомендуют использовать `psycopg2-binary` только для разработки и тестов. В продакшене это может привести к проблемам с производительностью или совместимостью (хотя риски безопасности минимальны).
**Рекомендация:** Заменить на `psycopg2` и установить необходимые системные зависимости (libpq-dev) на сервере.

### 5. Отладочные файлы
**Файл:** `debug_out.txt` (в .gitignore, но присутствует)
**Описание:** Наличие файлов для отладочного вывода.
**Рекомендация:** Убедиться, что в коде не осталось забытых вызовов записи в файлы (например `with open('debug_out.txt', 'a')`), так как они могут раскрыть конфиденциальные данные или забить дисковое пространство.

---
**Итог:** Рекомендуется в первую очередь исправить уязвимости CSRF (п.1) и проверку сигнатуры (п.2).
